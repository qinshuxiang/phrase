## 批次计划

词序固定为词库首次出现顺序，清单锁在 `research/sampling/all-words.json`，`npm run plan:knowledge -- --check` 复算并比对 `words_sha256`（`281bf58a…`）。

1. 前 100 词沿用 `pilot-100` 名单，保证已发布卡片的内容与 `id` 不变；
2. 其余 759 词按首次出现顺序切成 8 批，前 7 批各 95 词，末批 94 词；
3. 卡片按全量词序输出，`word_rank` 为 1—859 的连续序号；
4. `id` 始终取词名 sha1 前 10 位，批次调整不影响已有 `id`。

`entry_refs` 在构建时按当前词库重新聚合，同一词名的所有 `group_id` / `file_id` 全部并入该词卡片，不再保留抽样时的快照。

## 数据结构

顶层：`schema_version`、`generated_at`、`plan`、`stats`、`sources`、`cards[]`。运行时由 `src/lib/knowledge.js` 建词名索引，查询为纯函数。

单卡字段：

| 字段 | 说明 |
| --- | --- |
| `id` / `word` / `word_rank` / `batch` | `id` 由词名 sha1 前 10 位生成；`batch` 为 `pilot-100` 或 `b1`—`b8` |
| `lexical_status` / `variant_of` | `standard`、`variant`、`modern_phrase`、`uncertain` |
| `lookup` | 汉典查询状态、HTTP 状态码、页面 sha256、证据引用 |
| `entry_refs[]` | 该词名在词库中的全部 `group_id` / `file_id`，与词库逐条相等 |
| `readings` / `senses` | 拼音、注音、义项；义项通过 `reading_ids` 关联读音 |
| `origin` / `citations` | 出处与书证分开：汉典 xxjs 页只有书证，不反推出处 |
| `synonyms` / `antonyms` | 词典明列的近反义，附 `in_library` 是否在词库 |
| `register` | 感情色彩，沿用词库「日常用法」标签并标为整理 |
| `confusables[]` | 易混词、`basis`（同组/关联词/异形/人工挑选）、差异说明 |
| `conflicts[]` | 多源矛盾条目；全量为 0 |
| `verification` | 复核状态与说明 |

每个字段组都带 `provenance`：

- `kind=quote`：`source_name`、`source_url`、`retrieved_at`、`quote`（≤300 字，必须能在 `research/evidence/` 或人工稿中找到原文）、`evidence_ref`；
- `kind=derived`：`note` 必须以「整理（derived）」开头，并写明依据；
- `status`：`verified`、`single-source`、`reviewed`、`pending`、`missing`、`conflict`。交付时 `pending` 必须为 0。

## 差异说明的生成口径

925 条易混词条目全部标 `整理（derived）`。底稿由 `scripts/knowledge-confusables.mjs` 依据词库自身字段生成，不引入词库以外的判断，也不编造共同点：

1. 候选优先取「关联词」中出现的库内词。说明有效时写成「「候选」+ 说明；本词 + 释义」，主语方向不会颠倒；共同点、提醒、单字释义、指代不明（前者/后者）等说明一律丢弃。
2. 关联词没有可用候选时，取同组中释义最接近的词，用两词释义与「适用语境」对照成句。
3. 同组词只是主题相邻（相似度过低）时，改用词形相近的库内词，避免把无关成语凑成易混对。

抽检口径：每批随机读 10 条，检查方向、通顺度与候选相关性；发现的问题通过收紧过滤规则修正后重跑。差异句仍未经人工逐条复核。

## 来源分级

1. 汉典、教育部《成语典》——事实引用主源；
2. 人民日报易错字指南（学习强国转载）、中华字典、好查汉语词典——仅用于异形判断与缺字段补录，标 `single-source`；
3. 公考培训页——只作辨析线索，未作为事实来源。

## 命令

```bash
npm run plan:knowledge -- --check      # 复算全量词序与批次
npm run sample:knowledge -- --check    # 复算 100 词试点清单
npm run draft:knowledge -- --batch b1  # 生成指定批的差异稿底稿
npm run fetch:knowledge                # 抓取汉典，默认断点续跑；--force 重抓，--reparse 只重解析
npm run build:knowledge -- --check     # 重建卡片并比对字节
npm run verify:knowledge -- --strict   # 结构、引用、来源与体积断言
```

## 复核状态

- 事实字段：逐条取自汉典页面或人工记录的来源原文，`quote` 与归档文本做子串比对；
- 差异说明：由脚本依据词库关联词、释义与适用语境整理，标注「整理（derived）」，按批抽检，**尚未经人工逐条复核**；
- 因此 `verification.reviewer_type` 记为 `model`，不冒称人工复核。接入界面前建议按批抽查。
